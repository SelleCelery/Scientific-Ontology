## 0. 本文書の位置づけ

本文書は、平和を理念として語るだけでなく、組織境界、責任境界、ポート、プロトコル、履歴、監査、例外処理、返路、境界更新として実装・照合するための公開用仕様書である。

本文書は、Research Note [`Organizational_Boundary_and_Port_Model.ja.md`](../../05_Research_Notes/Cross_Domain_Ontological_Notes/Organizational_Boundary_and_Port_Model.ja.md) で整理した横断モデルを、社会境界設計へ適用できる粒度へ落とす。

研究ノートが所有するのは、組織境界、責任境界、ポート、プロトコル、履歴、監査、処理能力、境界更新の一般構造である。

本文書が所有するのは、その一般構造を用いて、次を事前・運用中・事後に照合するための公開手続である。

- 誰と誰の境界を接続するのか。
- 何を共有し、何を共有しないのか。
- どの差異を保持するのか。
- どの競争を許容し、どの破壊を止めるのか。
- 誰が通信、判断、説明、停止、修復を担うのか。
- どのポートから異議、例外、危機、再交渉を受け取るのか。
- どの負荷が弱い側、外部、自然、未来へ押し出されるのか。
- 何を未解決として残し、いつ再照合するのか。

本文書は、旧稿「生存競争の本質と非本質」に含まれていた概念的背景を保持する。

ただし、中心を存在強度の説明から、平和を運用可能にする境界設計へ移す。

同じフォルダの [`AI_Adoption_Collation_Checklist.md`](./AI_Adoption_Collation_Checklist.md) と同様に、本書は採否を自動決定する採点表ではない。

未照合を未照合として保持し、条件付き実施、試行、停止、再交渉、仕様変更へ分岐させるための照合表である。

## 1. 中心命題

平和は、争いが見えない状態ではない。

平和は、異なる存在相が、互いの境界、履歴、意味、責任を消されずに、相互作用、競争、交渉、撤退、再接続を継続できる境界状態である。

したがって、平和設計は次の問いから始める。

- 誰の境界が維持されるのか。
- 誰の境界が、平和の名の下に薄くされるのか。
- 誰が通信条件を決めるのか。
- 誰が拒否、保留、撤退できるのか。
- 誰が負荷を受け、誰が利益を得るのか。
- 誰が異議を申し立てられるのか。
- 誰が停止と再開を判断するのか。
- 破壊された境界を、誰が修復するのか。

合意が成立したことは、平和が成立したことと同じではない。

衝突が記録されていないことも、平和が成立したことと同じではない。

重要なのは、合意や静穏の背後で、異議、離脱、再交渉、説明、修復の返路が維持されているかである。

## 2. 本仕様書が扱うもの

本文書は、社会、制度、組織、共同体、企業、行政、国家、国際組織、プラットフォーム、AIを含む複合的な境界間相互作用について、次の観点を扱う。

1. 目的と対象境界
2. 存在相と差異の保持
3. 組織境界と責任境界
4. 通信ポートと異議申立て
5. プロトコルと翻訳条件
6. 権力差・非対称性・強制
7. 競争・資源・外部化
8. 例外・危機・停止・撤退
9. 履歴・ログ・監査・修復
10. Open Markerと境界更新

本文書は、平和条約そのものではない。

また、特定の政治体制、外交方針、経済制度、軍事政策、教育制度、宗教、民族、国家、組織を評価するものでもない。

特定事例へ適用する場合は、法務、外交、安全保障、公共政策、人権、地域史、文化、現場実務、当事者参加による個別確認を別途必要とする。

本文書は、次のものではない。

## 4. 使い方

本仕様書は、少なくとも次の段階で使用できる。

1. 制度、協定、組織間連携、共同事業、地域計画を設計する前に確認する。
2. 各項目について、誰の視点から回答したかを記録する。
3. 回答できない項目を `Open` として残す。
4. 権力の弱い側、影響を受ける外部、将来世代、自然環境から見た回答を別に確認する。
5. 条件付き実施では、条件、責任者、期限、停止条件、再照合点を明示する。
6. 実施後は、苦情、沈黙、退出、例外、負荷移転、環境変化を履歴として記録する。
7. 合意の維持ではなく、境界、判断可能性、修復可能性が維持されたかを評価する。

このチェックリストは、単独で記入しない方がよい。

可能であれば、少なくとも次の立場を分けて回答する。

- 設計・決定する側
- 実行・運用する側
- 直接影響を受ける側
- 異議を出しにくい側
- 外部化された負荷を受ける側
- 監査または第三者の側

回答が一致しないこと自体は失敗ではない。

その不一致が、どの境界、履歴、価値、コストの違いから生じているかを明示することが、照合の出発点になる。

## 5. 判定区分

各項目は、次の四段階で扱う。

| 判定 | 意味 | 推奨対応 |
|---|---|---|
| OK | 現時点で照合済み。必要な境界、責任、返路が確認できる。 | 合意・運用条件へ明記する。 |
| Conditional | 条件付きで相互作用を継続できる。 | 条件、責任者、期限、再評価点を明示する。 |
| Open | 未照合。閉じてはいけない。 | Open Markerとして記録し、追加確認または試行を行う。 |
| Risk | 境界破壊、責任消失、強制、外部化、返路喪失の危険がある。 | 実施停止、再設計、第三者確認、交渉条件の変更を行う。 |

`Open` は不合格ではない。

ただし、重要な未照合を `OK` と扱うことは、偽閉鎖である。

`Risk` は相手との関係断絶を自動的に意味しない。

通信条件、距離、権限、ポート、保護措置を再設計する必要があることを意味する。

## 6. 概念的背景：生存競争の本質と非本質

### 6.1 代理指標の争奪

生存競争は、物資、土地、お金、地位、権限、評価の奪い合いとして現れやすい。

これらは生存と社会運用に重要である。

しかし、それらは存在そのものではなく、存在を支え、社会的に照合する交換面である。

代理指標が存在価値そのものとして扱われると、多様な存在相が単一の競争空間へ押し込まれる。

その結果、比較、排除、独占、序列化が競争の中心になりやすい。

### 6.2 存在強度

本文書では、存在強度を、存在が世界との相互作用を継続し、履歴、意味、関係、能力、構造を形成し続ける可能性として読む。

理解、創造、学習、信頼、技術、文化、協力、責任処理、修復可能性は、存在強度を支える。

物資、地位、権限は、その条件または表れになりうる。

しかし、意味ループ、信頼、技術、責任処理、文化的継承、退出可能性が失われているなら、外部指標の増大だけで存在強度が高まったとはいえない。

### 6.3 自己定義と客観定義

自己定義とは、内部履歴、経験、創造、信念、意味、責任を通じて形成される存在である。

客観定義とは、資格、肩書き、評価、権限、収入、制度的位置づけなど、他者・制度との相互作用を通じて形成される存在である。

平和設計は、どちらか一方だけを正当化しない。

自己定義だけでは、公共的照合と他者への責任を失うことがある。

客観定義だけでは、存在を外部指標へ圧縮し、異なる存在相を同じ競争へ追い込むことがある。

### 6.4 複数の存在相

人間や組織は、教育、研究、家庭、労働、ケア、芸術、技術、地域、信仰、遊びなど、複数の存在相に属する。

すべてを単一の尺度で評価しないことは、競争を消すことではない。

競争空間を必要な範囲へ限定し、異なる存在相が相互消去しないようにすることである。

## 7. 最小12問

平和、連携、協定、共同事業、制度変更を設計するとき、最低限、次の12問を確認する。

1. 誰と誰の境界を接続しようとしているか。
2. 共有する目的と、共有しない領域は明確か。
3. 各主体が保持すべき履歴、文化、生活、判断領域は何か。
4. 誰が通信条件とルールを決めているか。
5. 力の弱い側が、拒否、保留、異議、撤退を選べるか。
6. 判断、実行、監督、説明、停止、修復の責任境界は明確か。
7. 通常、例外、異議、緊急、再交渉のポートがあるか。
8. 競争によって、誰の存在相、生活基盤、判断可能性が失われるか。
9. 内部秩序のための負荷が、外部、自然、未来へ押し出されていないか。
10. 合意後の苦情、沈黙、退出、失敗、環境変化を再照合できるか。
11. 停止、撤退、距離変更、再交渉の条件があるか。
12. 未解決項目をOpen Markerとして保持しているか。

## 8. 平和境界システムの最小モデル

本文書では、平和を維持する境界系を次の要素で表す。

```text
Peace Boundary System
  = Distinct Actors
  + Preserved Boundaries
  + Shared and Non-shared Purposes
  + Responsibility Boundaries
  + Ports
  + Protocols
  + Asymmetry Controls
  + History and Audit
  + Appeal and Exit Paths
  + Repair and Boundary Update
```

### 8.1 Distinct Actors / 異なる主体

主体は、個人、共同体、組織、企業、行政、国家、国際組織、AIエージェント群などである。

比較可能であっても同一ではない。

法的地位、身体性、強制力、資源、時間射程、責任能力は異なる。

### 8.2 Preserved Boundaries / 保持される境界

各主体が、何を内部として守り、どこから外部と交渉するかを明示する。

境界保持は、孤立や排外を意味しない。

接触条件を自ら照合できる状態を意味する。

### 8.3 Shared and Non-shared Purposes / 共有領域と非共有領域

すべてを共有しなくても協力は成立する。

共有目的、競合目的、非共有領域を区別する。

非共有領域を即座に敵対または欠陥と扱わない。

### 8.4 Responsibility Boundaries / 責任境界

誰が設計、許可、実行、監督、説明、停止、修復を担うかを区別する。

機能を委託しても、責任の返路を消さない。

### 8.5 Ports / ポート

通常通信、例外、異議、緊急、外交、監査、学習、撤退を別の入口として設計する。

### 8.6 Protocols / プロトコル

誰が、何を、どの条件で受け取り、どう翻訳し、どこへ返すかを定める。

### 8.7 Asymmetry Controls / 非対称性制御

資源、情報、法的地位、強制力、発話力の差を可視化し、弱い側の沈黙を合意と誤認しない。

### 8.8 History and Audit / 履歴と監査

合意だけでなく、例外、苦情、拒否、退出、修復、条件変更を記録し、次の判断へ接続する。

### 8.9 Appeal and Exit Paths / 異議と退出の返路

異議申立て、再審査、距離変更、撤退、再交渉を、裏切りや敵対へ自動変換しない。

### 8.10 Repair and Boundary Update / 修復と境界更新

破損した境界を、責任、補償、制度変更、通信条件変更へ戻す。

## 9. 照合チェックリスト本体

### A. 目的と対象境界

| No. | 確認項目 | 照合問い | 判定 |
|---:|---|---|---|
| A-1 | 平和または連携の目的が明示されているか。 | 何を守り、何を可能にするための合意・制度か。 | |
| A-2 | 目的が「衝突を見えなくすること」へ縮退していないか。 | 苦情や異議が消えることを成果としていないか。 | |
| A-3 | 対象となる主体と境界が明確か。 | 誰と誰の間を設計するのか。影響を受ける外部は誰か。 | |
| A-4 | 共有目的と非共有領域を区別しているか。 | 全面同意を要求せずに協力できるか。 | |
| A-5 | 競合目的が記録されているか。 | 安全、自由、成長、文化、生活、環境などの競合を隠していないか。 | |
| A-6 | 成功条件が単一指標へ圧縮されていないか。 | 件数、成長率、静穏、支持率だけで平和を測っていないか。 | |

### B. 存在相と差異の保持

| No. | 確認項目 | 照合問い | 判定 |
|---:|---|---|---|
| B-1 | 各主体の履歴と存在相が記述されているか。 | 生活、文化、役割、関係、過去の損害を無視していないか。 | |
| B-2 | 異なる存在相を単一の評価軸へ押し込めていないか。 | 経済価値や制度適合だけで存在を測っていないか。 | |
| B-3 | 自己定義と客観定義の両方を扱っているか。 | 当事者の自己理解と公共的照合を分離して確認したか。 | |
| B-4 | 少数側・周縁側の差異を欠陥として扱っていないか。 | 多数派への同化を平和の条件にしていないか。 | |
| B-5 | 共有しない権利が残されているか。 | 思想、文化、生活、情報の全面共有を要求していないか。 | |
| B-6 | 翻訳不能な残差を保持できるか。 | 理解できないことを、虚偽、無価値、敵意と即断していないか。 | |
| B-7 | 差異が固定的な属性ラベルへ変換されていないか。 | 個人や集団を単一の思想・民族・役割へ閉じ込めていないか。 | |

### C. 組織境界と責任境界

| No. | 確認項目 | 照合問い | 判定 |
|---:|---|---|---|
| C-1 | 内部と外部の責任範囲が明確か。 | 誰が何を引き受け、何を引き受けないか。 | |
| C-2 | 目的設定、設計、許可、実行の主体が分かるか。 | 決定が無主体化されていないか。 | |
| C-3 | 監督、説明、改善、停止の主体が分かるか。 | 問題発生後に誰も構造を変えられない状態ではないか。 | |
| C-4 | 機能委託によって責任が消えていないか。 | 委託先、現場、技術、AIへ責任が洗浄されていないか。 | |
| C-5 | 受益主体が責任から切り離されていないか。 | 利益を得る主体が負荷と修復を他者へ移していないか。 | |
| C-6 | 責任主体に実際の権限と資源があるか。 | 名目責任だけを弱い部署や個人へ置いていないか。 | |
| C-7 | 責任境界の変更履歴が残るか。 | 組織再編、委託、緊急措置で責任が曖昧になっていないか。 | |
| C-8 | 法的責任と実務上の責任のずれを確認したか。 | 契約上は明確でも、現場が無償で補完していないか。 | |

### D. ポートと通信可能性

| No. | 確認項目 | 照合問い | 判定 |
|---:|---|---|---|
| D-1 | 通常の協議ポートがあるか。 | 定期的に情報、要求、変更を交換できるか。 | |
| D-2 | 例外ポートがあるか。 | 通常手続に入らない事案を受け取れるか。 | |
| D-3 | 異議申立てポートがあるか。 | 判断を受けた側が理由と再審査を求められるか。 | |
| D-4 | 緊急ポートがあるか。 | 危機時に通常の優先順位を変更できるか。 | |
| D-5 | 外交・再交渉ポートがあるか。 | 関係を切らずに条件を変更できるか。 | |
| D-6 | 退出・距離変更ポートがあるか。 | 全面服従か断絶かの二択になっていないか。 | |
| D-7 | ポート利用者への報復防止があるか。 | 苦情、内部告発、拒否が不利益へ直結しないか。 | |
| D-8 | ポートの処理能力が確保されているか。 | 入力過多が定型回答、放置、担当者疲弊へ流れていないか。 | |

### E. プロトコルと翻訳

| No. | 確認項目 | 照合問い | 判定 |
|---:|---|---|---|
| E-1 | 通信主体と権限が明確か。 | 誰が代表し、何を決定できるか。 | |
| E-2 | 受け入れる情報と形式が明確か。 | 専門語、言語、証拠形式が一方だけに有利でないか。 | |
| E-3 | 翻訳過程が可視化されているか。 | 誰が何を要約・変換・省略したか分かるか。 | |
| E-4 | 翻訳不能残差を記録するか。 | 無理な同意語化や価値の均しをしていないか。 | |
| E-5 | 保留と再照合の条件があるか。 | 即答できないことを拒否や同意へ変換していないか。 | |
| E-6 | エスカレーション経路があるか。 | 現場で処理不能な事案を上位または第三者へ送れるか。 | |
| E-7 | プロトコルを変更できるか。 | 手続に入らない現実を、手続違反として切り捨てていないか。 | |

### F. 権力差・非対称性・強制

| No. | 確認項目 | 照合問い | 判定 |
|---:|---|---|---|
| F-1 | 資源、情報、法的地位、強制力の差を記録したか。 | 対等という形式だけで実質差を隠していないか。 | |
| F-2 | 弱い側が拒否できるか。 | 拒否が失職、排除、生活喪失、報復へ直結しないか。 | |
| F-3 | 沈黙を同意として扱っていないか。 | 発話不能、情報不足、疲弊、恐怖を確認したか。 | |
| F-4 | 交渉参加に必要な資源が保障されているか。 | 時間、翻訳、専門支援、移動、情報アクセスがあるか。 | |
| F-5 | ルール形成権が一方へ集中していないか。 | 強い側が基準、証拠、期限、議題を独占していないか。 | |
| F-6 | 保護措置が恒久的支配へ変質していないか。 | 安全、支援、秩序を理由に自己決定を奪っていないか。 | |
| F-7 | 第三者または独立監査を利用できるか。 | 内部ポートだけでは異議を処理できない場合の返路があるか。 | |
| F-8 | 強制を用いる場合の限定条件があるか。 | 必要性、比例性、期限、監査、解除条件が明示されているか。 | |

### G. 競争・資源・外部化

| No. | 確認項目 | 照合問い | 判定 |
|---:|---|---|---|
| G-1 | 何をめぐる競争か明示されているか。 | 資源、地位、意味、発話空間、生活基盤のどれか。 | |
| G-2 | 競争範囲を限定できているか。 | 全人格、全生活、全存在価値を賭ける競争になっていないか。 | |
| G-3 | 最低限保持すべき境界があるか。 | 競争に敗れても、生活、尊厳、異議、再参加可能性が残るか。 | |
| G-4 | 単一指標が多様な存在相を潰していないか。 | 価格、効率、得票、成績だけで全体を決めていないか。 | |
| G-5 | 内部秩序のコストを外部へ押し出していないか。 | 下請け、家庭、弱者、他地域、自然、未来へ負荷を移していないか。 | |
| G-6 | 外部化された負荷を追跡できるか。 | 誰が受け、どの時間で返るかを記録しているか。 | |
| G-7 | 補償、修復、再配分の返路があるか。 | 利益と損失が固定的に分離されていないか。 | |
| G-8 | 資源不足を敵対属性へ変換していないか。 | 設計・配分・処理能力の問題を、集団の本質へ帰属していないか。 | |

### H. 例外・危機・安全・停止

| No. | 確認項目 | 照合問い | 判定 |
|---:|---|---|---|
| H-1 | 例外を受け取る主体がいるか。 | 通常手続に合わない事案が個人の抱え込みにならないか。 | |
| H-2 | 危機の定義と判断主体が明確か。 | 危機名目を一方的な権限拡大に使えないか。 | |
| H-3 | 緊急措置に期限と解除条件があるか。 | 例外が恒常運用へ変わらないか。 | |
| H-4 | 停止権限が実行可能か。 | 名目的権限だけで、実際には止められない構造ではないか。 | |
| H-5 | 撤退と再開の条件があるか。 | 断絶か継続かだけでなく、距離調整が可能か。 | |
| H-6 | 被害拡大を防ぐ暫定境界があるか。 | 隔離、保留、アクセス制限、第三者管理を設計できるか。 | |
| H-7 | 安全措置が対象者の発話権を消していないか。 | 保護の名の下に当事者を意思決定から排除していないか。 | |
| H-8 | 危機後の権限・履歴・損害を再照合するか。 | 正常化後に緊急措置を検査する仕組みがあるか。 | |

### I. 履歴・ログ・監査・修復

| No. | 確認項目 | 照合問い | 判定 |
|---:|---|---|---|
| I-1 | 合意、判断、根拠、条件を記録するか。 | 後から誰が何を決めたか確認できるか。 | |
| I-2 | 例外、異議、拒否、退出を記録するか。 | 成功事例だけを履歴として残していないか。 | |
| I-3 | ログが次の判断へ接続されるか。 | 保存だけで、検索・照合・改善に使えない状態ではないか。 | |
| I-4 | 監査が第一義と実運用を比較するか。 | 手続遵守だけで、誰が壊れたかを見ているか。 | |
| I-5 | 監査系そのものを監査できるか。 | 特定の苦情や弱い側の負荷だけ見えなくなっていないか。 | |
| I-6 | 損害認定、説明、補償、修復の主体がいるか。 | 問題確認後に、誰も修復できない状態ではないか。 | |
| I-7 | 修復後の後続条件を追跡するか。 | 謝罪・補償・制度変更が実際に返路を回復したか。 | |

## 10. 比較表：静穏としての平和と境界設計としての平和

| 観点 | 静穏としての平和 | 境界設計としての平和 |
|---|---|---|
| 衝突 | 見えないほどよい。 | 安全なポートから観測・処理できる。 |
| 差異 | 同化または私事化する。 | 共有領域と非共有領域を分けて保持する。 |
| 同意 | 形式的同意を重視する。 | 情報、拒否、保留、撤退可能性を確認する。 |
| 責任 | 全体の善意へ拡散する。 | 設計、許可、実行、監督、修復へ分ける。 |
| 異議 | 秩序を乱すものとして扱う。 | 境界の限界を示す入力として扱う。 |
| 安全 | 事故や対立がないこと。 | 危険時に停止、隔離、異議、修復ができること。 |
| 履歴 | 合意と成果を保存する。 | 例外、拒否、損害、修復も保存する。 |
| 競争 | 勝敗に統合する。 | 競争領域と最低保障境界を分ける。 |
| 外部化 | 内部安定の外側を見ない。 | 負荷の送り先と時間的返りを追跡する。 |
| 更新 | 合意を固定する。 | 環境変化に応じて境界と条件を再交渉する。 |

## 11. 比較表：統合・同化と境界保持型協力

| 観点 | 統合・同化型 | 境界保持型協力 |
|---|---|---|
| 目的 | 一つの目的へ統合する。 | 必要な共有目的だけを設定する。 |
| 差異 | 未熟、障害、非効率として減らす。 | 作用とコストを照合しながら保持する。 |
| 言語 | 共通語への完全翻訳を求める。 | 翻訳不能残差を残す。 |
| 参加 | 全面的参加か離脱か。 | 部分参加、保留、距離変更を認める。 |
| ルール | 中心側の規則を標準化する。 | 境界間プロトコルとして交渉する。 |
| 権力 | 形式的平等で処理する。 | 実質的非対称性を補正する。 |
| 成果 | 一体化の度合い。 | 相互作用と自己境界の両立。 |

```text

翻訳不能または競合している差分: 事業効率と生活履歴の価値
権力差・資源差: 事業者と個別店舗の交渉資源に大きな差がある
放置した場合のリスク: 形式的合意後に退出・廃業が集中する
暫定的な保護条件: 工区分割、相談ポート、営業補償の仮条件
確認に必要な情報・参加者: 店舗別影響、歩行調査、住民・利用者参加

再照合期限: 実施設計確定前
停止・撤退条件への影響: 主要動線の代替不能が判明した場合は工程再設計
次の処置: 小規模試行と影響記録を実施する
```

## 15. 照合後の分岐

| 状態 | 判断 | 対応 |
|---|---|---|
| 主要境界・責任・返路がOK | 実施可能 | 条件、監査、再照合日を明記する。 |
| 一部がConditional | 条件付き実施 | 保護条件、責任者、期限、停止条件を明記する。 |
| 重要項目がOpen | 保留または小規模試行 | 追加参加、影響調査、暫定ポートを設計する。 |
| 権力差が未補正 | 再設計 | 独立支援、情報保障、拒否・異議経路を追加する。 |
| 責任境界が不明 | 実施不可に近い | 説明、停止、修復主体が明確になるまで進めない。 |
| 異議・退出の返路がない | 実施不可に近い | Appeal / Exit Portを設計する。 |
| 外部化先が不明 | 追加調査 | 自然、他地域、家庭、将来への負荷を追跡する。 |
| 重大なRisk | 停止または抜本再設計 | 第三者確認、条件変更、代替案検討を行う。 |

## 16. 事前レビュー用短縮版

時間が限られている場合、最低限、次を確認する。

| No. | 問い | 判定 |
|---:|---|---|
| 1 | 誰と誰の境界を接続する設計か。 | |
| 2 | 共有目的と非共有領域は明確か。 | |
| 3 | 弱い側が拒否、保留、異議、撤退できるか。 | |
| 4 | 設計、実行、監督、説明、停止、修復の責任は明確か。 | |
| 5 | 例外・異議・緊急・再交渉のポートがあるか。 | |
| 6 | 権力差、情報差、資源差を補正しているか。 | |
| 7 | 競争が全人格・全生活の否定へ広がっていないか。 | |
| 8 | 内部安定のコストを外部、自然、未来へ押し出していないか。 | |
| 9 | 停止、距離変更、撤退、再開の条件があるか。 | |
| 10 | 苦情、沈黙、退出、例外を履歴として保持するか。 | |
| 11 | 修復・補償・境界更新を実行できる主体がいるか。 | |
| 12 | 未照合をOpen Markerとして残しているか。 | |

重要項目のうち3つ以上が `Open` または `Risk` である場合、全面実施より、追加照合、小規模試行、条件変更を優先する。

ただし、数だけで機械的に決めない。

拒否不能、責任主体不在、異議ポート不在、重大な外部化などは、単独でも実施停止に近い問題になりうる。

## 17. 適用例

### 17.1 組織間連携

共同事業の目的だけでなく、責任分担、情報共有範囲、例外、撤退、成果物、失敗履歴の返路を設計する。

### 17.2 地域・行政

住民説明を一方向の周知にせず、異議、影響、代替案、再設計要求を受け取るポートとして扱う。

### 17.3 市場と競争

価格競争を否定せず、最低保障、参入可能性、外部化、独占、修復不能な退出を別に照合する。

### 17.4 教育・文化

共通基準を持ちながら、単一評価軸が異なる才能、履歴、文化、学習経路を消さないようにする。

### 17.5 プラットフォーム

利用規約への同意だけでなく、説明、異議、アカウント停止、データ移行、退出、再審査のポートを設計する。

### 17.6 AI

AIを調停者または中立主体として自動的に扱わない。

入力、学習履歴、権限、出力、異議、停止、責任返路を組織境界へ実装する。

詳細は [`AI_Adoption_Collation_Checklist.md`](./AI_Adoption_Collation_Checklist.md) を参照する。

### 17.7 自然・将来世代

直接発話できない境界主体について、代弁主体、観測指標、長期履歴、停止条件、修復義務を設計する。

## 18. 公開・制度設計向けの要約文

平和は、単に衝突が見えない状態ではない。

異なる個人、共同体、組織、国家が、それぞれの境界、履歴、意味、責任を保持したまま、通信、競争、協力、異議、撤退、再交渉を継続できる状態である。

そのためには、善意や理念だけでなく、責任境界、通信ポート、例外処理、異議申立て、履歴、監査、停止条件、修復経路を設計する必要がある。

合意の成立は重要である。

しかし、合意が誰の沈黙、疲弊、退出、外部化によって維持されているかを照合しなければ、平和は静穏の記号へ縮退する。

本文書は、特定の制度や政策を決めるものではない。

平和を、境界を消すことではなく、境界間の責任ある通信として設計するための公開照合表である。

## 20. 最小定義

| 用語 | 定義 |
|---|---|
| 平和 | 異なる存在相が境界と履歴を保持したまま、破壊的でない相互作用、異議、撤退、再接続を継続できる状態。 |
| 存在相 | 個人や組織が、生活、文化、役割、関係、履歴を通じて成立する異なる存在の面。 |
| 存在強度 | 履歴、意味、関係、能力、構造を形成し、相互作用を継続できる可能性。 |
| 組織境界 | 組織が内部、外部、通信、責任、履歴、処理能力を定義する動的境界。 |
| 責任境界 | 設計、許可、実行、監督、説明、停止、修復を誰が担うかの境界。 |
| ポート | 特定の通信を、一定条件で受け取り、変換し、返す境界口。 |
| 外交ポート | 異なる境界を内部化せず、通信と再交渉を維持するポート。 |
| 異議申立てポート | 判断を受けた側が、説明、再審査、修正を求める返路。 |
| 境界保持型協力 | 全面的同化ではなく、必要な共有領域と非共有領域を区別した協力。 |
| 非対称性制御 | 資源、情報、強制力、発話力の差を可視化し、拒否・異議・参加条件を補正すること。 |
| 残差 | 現行の分類や合意では閉じきれないが、再照合可能な差分。 |
| 残渣 | 処理後も身体、制度、関係、環境、未来に沈殿し、作用し続ける履歴的負荷。 |
| Open Marker | 未解決を解決済みにせず、責任者、期限、再照合条件とともに保持する印。 |
| 偽閉鎖 | 未解決、異議、負荷が残っているのに、合意・静穏・手続完了によって処理済みと扱うこと。 |
| 境界更新 | 異常、例外、残差、環境変化を受けて、目的、責任、ポート、プロトコルを修正すること。 |

## 21. 非主張境界

本文書は、平和を一つの制度、思想、外交方式へ還元しない。

また、次を主張しない。

- すべての紛争が対話によって解決する。
- すべての境界開放が善である。
- すべての境界閉鎖が悪である。
- 競争は常に有害である。
- 強制または安全措置は常に不要である。
- 境界設計だけで歴史的・法的・軍事的・経済的問題を解決できる。
- 本チェックリストによって当事者の権利や正当性を自動判定できる。

必要な遮断、隔離、防御、制裁、緊急措置がある場合も、それらの必要性、比例性、期限、責任、監査、解除条件を照合する。

## 22. 要約

平和は、境界を消すことではない。

異なる存在相が、互いの境界、履歴、意味、責任を保持したまま、通信と相互作用を継続できる状態である。

その状態は、理念だけでは維持できない。

目的、責任境界、ポート、プロトコル、非対称性制御、履歴、監査、異議、停止、修復、境界更新が必要になる。

本仕様書は、平和を採点するものではない。

誰の境界が守られ、誰の沈黙によって静穏が成立し、どの負荷が外部化され、どの返路が失われているかを照合するためのものである。

未解決を閉じない。

差異を即座に敵対へ変換しない。

異議を平和の失敗ではなく、境界の状態を知らせる入力として扱う。

そして、壊れた境界を、説明、責任、修復、再交渉へ戻す。

これが、本書における平和の公開実装である。
