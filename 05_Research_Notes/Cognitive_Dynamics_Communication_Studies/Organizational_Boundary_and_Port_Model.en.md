## 0. Positioning

This document presents a cross-domain model for implementing a shared purpose as organizational boundaries, responsibility boundaries, ports, protocols, history, audit, exception handling, and boundary updates.

This document owns one question:

> Once a purpose has been shared within an organization, how can it be implemented as a structure that specifies who receives which communication at which boundary, transforms it through which procedure, and returns it to which responsibility boundary?

This document does not generate cognitive axes. The generation of cognitive direction is handled by [`Entropy_Attributed_Difference_and_Cognitive_Axis_Formation.en.md`](../../02_Raj_Beauty/Entropy_Attributed_Difference_and_Cognitive_Axis_Formation.en.md).

This document does not define existence-phase compression. The diagnosis of single-metric compression is handled by [`Compression_of_Existence_Phases.en.md`](Compression_of_Existence_Phases.en.md).

This document does not decide which ports should be selected or which differences should be held, commensurated, or reopened. Those dynamics are handled by [`Boundary_Diplomacy_and_Port_Allocation.en.md`](Boundary_Diplomacy_and_Port_Allocation.en.md).

This document receives the following from those upstream documents:

- primary purpose and competing purposes;
- cognitive axes and residual profiles;
- existence phases that must be preserved;
- ports to be used and their reopening conditions;
- differences to be accepted;
- expected transformations;
- negentropy to be returned to society;
- externalizations that will not be permitted; and
- stop conditions.

It then implements them as follows.

```text
purpose
  ↓
organizational boundary
  ↓
responsibility boundary
  ↓
organizational port
  ↓
protocol
  ↓
history / audit
  ↓
exception handling / appeal
  ↓
boundary update
  ↓
return to purpose
```

## 1. Why Purpose Alone Is Not Implementation

An organization does not operate merely by declaring a purpose.

Purpose is transformed into roles, authority, budgets, evaluation, information pathways, exceptions, records, and stop conditions.

If this transformation is ambiguous, the purpose does not reach operational sites.

If only the name of the purpose arrives while responsibility, appeal, audit, and stopping authority do not, the purpose degenerates into an order or slogan.

Even when an organization declares "safety," safety is not implemented if there is no port through which accidents can be reported.

Even when it declares that it "values people," that purpose is not connected to the organizational boundary if there is no responsible actor who records exhaustion, corrects assignments, and stops work.

Even when it declares that it will "make use of AI," AI imports a responsibility vacuum into the organization if there are no ports for handling input, authority, judgment, explanation, exceptions, and withdrawal.

Implementing a purpose does not mean decomposing it into detailed commands.

It means transforming the purpose into responsible communication and revisable history.

## 2. The Organization as a Boundary

An organization is not merely a collection of people.

This document reads an organization as a dynamic boundary that retains the following elements.

```text
Organization
  = Boundary
  + Purpose
  + Responsibility
  + Organizational Ports
  + Protocols
  + History
  + Processing Capacity
  + Return Paths
  + Boundary Update
```

### 2.1 Boundary

Defines what is treated as internal and what is treated as external.

### 2.2 Purpose

Defines what the organization receives, what it transforms that input into, and what it returns.

### 2.3 Responsibility

Defines who authorizes, supervises, explains, improves, stops, and retains history.

### 2.4 Ports

Define which types of communication are accepted, processed, and returned under which conditions.

### 2.5 Protocols

Define who transforms received communication into which form and where it is routed.

### 2.6 History

Retains past contacts, decisions, exceptions, failures, and corrections in forms that change how subsequent communication is received.

### 2.7 Processing Capacity

Defines how much difference, exception, contradiction, complaint, and crisis can be processed without externalization.

### 2.8 Return Paths

Define pathways through which outputs, responsibility, objections, requests for correction, and residuals return to the next processing actor or to the original purpose.

### 2.9 Boundary Update

Modifies organizational structure in response to anomalies that cannot be processed through current boundaries, roles, authority, ports, or protocols.

This definition is not limited to companies.

Communities, public administrations, schools, hospitals, research organizations, open-source software projects, states, international organizations, and groups of AI agents can also be compared as boundary systems operating under different conditions.

Comparability, however, does not mean identity.

## 3. Converting Primary Purpose into a Transformation Contract

What an organization receives as entropy and returns as negentropy depends on what it establishes as its primary purpose.

The organization's self-definition should be expressed not as a slogan, but as a transformation contract.

| Item | Question |
|---|---|
| Primary Purpose | What does the organization seek to protect or increase, and what must it not lose? |
| Accepted Difference | Which disorder, pain, contradiction, danger, or demand does it accept internally? |
| Transformation | Into which capability, procedure, relation, or meaning does it transform the accepted difference? |
| Returned Value | What does it return to society, users, members, nature, and the future? |
| Prohibited Externalization | To whom must it not transfer burdens that should be processed internally? |
| Responsible Actor | Who assumes responsibility for the success, exceptions, failure, and explanation of the transformation? |
| Time Horizon | For how long are downstream conditions tracked? |
| Stop Condition | What occurrence will stop the transformation and return the organization to its purpose? |

A hospital receives pain, illness, inability to diagnose, and insufficient care, and attempts to return recovery, explanation, care, and possibilities for choice.

A school receives unorganized experience, inability to learn, isolation, and lack of knowledge, and attempts to return understanding, learning pathways, shared inquiry, and possibilities for future action.

A research organization receives unorganized knowledge, unverified hypotheses, and fragmented findings, and attempts to return verifiability, counterexamples, commensurability, and publicly available knowledge.

Here, entropy and negentropy are not thermodynamic quantities. They form a conceptual model for reading what an organization accepts as an unorganized burden and what it seeks to return as order, meaning, care, and capacity for judgment.

## 4. Organizational Boundary

An **Organizational Boundary** is a dynamic boundary through which an organization defines its interior, exterior, communication, responsibility, history, and processing capacity.

The interior is not the inside of a building. It is the domain the organization accepts as an object of responsibility, processing, explanation, and history retention.

The exterior is not an irrelevant domain. It lies outside the organization's authority or purpose while still exchanging communication, burdens, and returns with the organization.

A boundary changes through purpose, law, authority, technology, crisis, social expectations, members' capabilities, outsourcing, merger, withdrawal, and histories of failure.

### 4.1 Boundary Ambiguity

- It is unclear who processes a matter.
- It is unclear who explains it.
- It is unclear who can stop it.
- A problem continues moving between departments.
- Benefits are internalized while burdens are externalized.

### 4.2 Boundary Rigidity

- External change cannot be received.
- Exceptions are processed as rule violations.
- Appeals are treated as hostility.
- Internal heuristics become doctrine.
- Differences that cannot be processed are pushed back outside.

A stable Organizational Boundary can distinguish what it receives, under which conditions, through which port, and where it returns the result.

## 5. Responsibility Boundary

A **Responsibility Boundary** is the boundary not only of action, but also of the actors who authorize, design, supervise, explain, improve, stop, and retain the history of that action.

> **Functions can be delegated. Responsibility cannot be erased through delegation.**

Outsourcing, division of labor, automation, and the use of AI change the placement of functions.

That change of placement does not itself erase responsibility.

Responsibility can be decomposed at least into:

- purpose setting;
- design;
- authorization;
- execution;
- supervision;
- receipt of benefit;
- explanation;
- improvement;
- stopping; and
- history retention.

Even when these are distributed, the return path must not be lost.

### 5.1 Responsibility Laundering

```text
commissioning party
  → contractor
  → subcontractor
  → frontline worker
  → automated system
  → AI output
  → user's own responsibility
```

Even when functions are distributed through this chain, history remains concerning who authorized the operation, who benefited, who could have known about the anomaly, and who possessed stopping authority.

A Responsibility Boundary is not identical to legal responsibility. Legal conclusions are determined through applicable law, contracts, evidence, and jurisdiction.

## 6. Organizational Port

Within the organizational implementation layer, an **Organizational Port** is a boundary opening through which a particular type of communication is accepted, transformed, processed, and returned at an Organizational Boundary.

An organization cannot process everything through a single entrance.

Research, sales, legal affairs, education, recruitment, finance, complaints, crisis, audit, and diplomacy require different conditions.

### 6.1 Minimum Specification of an Organizational Port

| Item | Content |
|---|---|
| Port Name | Name and target communication |
| Purpose | Why the port is necessary |
| Accepted Input | Accepted differences, formats, and scope |
| Actor | Who may use it |
| Authority | What may be decided or changed |
| Transformation | Into which form the input is transformed |
| Capacity | How much can be processed |
| Escalation | Where unprocessable input is sent |
| Output | What is returned, and to whom |
| Return Path | How objections, corrections, and additional information are returned |
| Logging | What is retained as history |
| Stop / Reopen | Conditions for stopping and reopening |

### 6.2 Organizational Port Types

- Service Port
- Exception Port
- Appeal Port
- Audit Port
- Emergency Port
- Learning Port
- Diplomatic Port
- AI Port
- Depth Port

A Depth Port sends differences that cannot be closed on the current logical plane while retaining them as unresolved together with their history and conditions for re-collation.

### 6.3 Port Absence

Communication does not disappear merely because the necessary port is absent.

Complaints become informal conversation, anomalies become an individual's private burden, exceptions become rule violations, requests for correction become resignation, and safety objections become silence.

### 6.4 Port Overload

Input exceeding capacity appears as waiting time, template responses, discarded exceptions, omitted explanation, transfer of responsibility to the inputting party, and exhaustion at operational sites.

## 7. Protocol

A **Protocol** is a boundary procedure that specifies who transforms what into which form, under which conditions, and where it is returned after communication has been received.

A protocol is not merely a manual.

```text
Who
What
Conditions
Transform
Route
Return
Escalate
Log
Stop / Reopen
```

When a protocol becomes rigid, only what conforms to the rules is treated as reality.

The aim is not to eliminate exceptions, but to specify who handles them, where, and under what responsibility.

---

## 8. Processing Capacity

Processing Capacity is not merely the number of personnel or the amount of computation available.

It includes:

- capacity to understand input;
- capacity to translate;
- capacity to hold exceptions;
- capacity to handle conflict among multiple purposes;
- capacity to retrieve history;
- capacity to return explanations;
- capacity to re-collate appeals; and
- capacity to follow long-term downstream conditions.

A mature organization possesses a holding state.

Holding requires a reason, a responsible actor, reopening conditions, a deadline for re-collation, an explanation to the inputting party, and history retention.

Input exceeding processing capacity is externalized into overtime at operational sites, waiting by users, care burdens on families, discharge into natural environments, and repair costs borne by future generations.

## 9. History, Logging, and Audit

A log is a record that preserves events.

History is a structure through which those records connect to subsequent judgment, responsibility, modes of reception, and boundary updates.

Even a large volume of logs does not function as history without retrieval, collation, authority, and pathways for improvement.

At minimum, records should distinguish input, judgment, grounds, execution, exception, holding, appeal, reconsideration, stopping, and changes to purpose, boundaries, or protocols.

Audit is not merely compliance with rules.

It asks:

- Does operation remain consistent with the primary purpose?
- Can ports receive the communication they need to receive?
- Has responsibility disappeared downstream?
- Are burdens being externalized?
- Do exceptions reach boundary updates?
- Can stop conditions actually be executed?

The audit system itself has blind spots.

If the same anomaly is repeatedly discovered later, not only the target but also the observation system must be audited.

---

## 10. Normality, Anomaly, Exception, and Boundary Update

The purpose of delegating normal processing to systems is not to make humans continue watching the normal.

It is to redirect human attention toward deviation, exception, contradiction, and what remains unprocessed.

An anomaly is both a precursor to breakdown and a sign of environmental change or new demand.

The anomalies most difficult to see are those that continue producing results.

- concentration of burden in a particular individual;
- dependence on tacit knowledge;
- absorption through overtime;
- exception handling through goodwill;
- self-completion by users; and
- transfer of burdens to the external environment.

Boundary updates proceed through the following cycle.

```text
delegate normal processing to systems
  ↓
observe deviations / anomalies / exceptions
  ↓
identify the limits of the current boundary
  ↓
re-collate purpose / responsibility / ports / protocols
  ↓
incorporate the result into new normal processing
  ↓
reinspect blind spots in the audit system
```

## 11. Implementing Boundary CA

Observation alone is insufficient to establish Boundary CA.

| Question | Organizational Implementation |
|---|---|
| Who became exhausted? | Load indicators, interviews, appeals, and histories of withdrawal |
| What became invisible? | Exception records, unclassified input, and audit of the audit system |
| Where did the cost move? | Externalization destinations, waiting, unpaid labor, and environmental burdens |
| Which Responsibility Boundary is ambiguous? | Role table for authorization, design, supervision, explanation, and stopping |
| Which Return Path was lost? | Appeal Port, reconsideration, and escalation |
| What can be corrected? | Procedures, boundaries, metrics, sharing, purpose, and stopping |

Even if audit results are recorded, CA becomes ritualized when authority, metrics, and purpose cannot be changed.

---

## 12. Externalization, Residuals, and Residue

Externalization is not always wrong in itself.

Division of labor, delegation, disposal, discharge, insurance, and transfer may be necessary.

The problem begins when the return paths of the externalized burden and responsibility are lost.

A **Residual** is a difference that cannot be closed through current classifications, explanations, or protocols but remains available for re-collation.

**Residue** is a historical burden that remains deposited in bodies, institutions, relations, environments, and the future after processing and continues to act.

The negentropy of an organization cannot be evaluated through internal order alone.

If excessive residue is pushed outside in order to organize the interior, that order is local.

## 13. Organizational Implementation of Diplomacy and Gateways

Diplomacy is not a function limited to states.

Diplomatic functions connect different Responsibility Boundaries among companies, public administrations, hospitals, universities, open-source software projects, research organizations, and communities.

A Diplomatic Port maintains communicability while preserving different boundaries, histories, purposes, and constraints instead of internalizing the other party.

A gateway transforms communication between different protocols.

The necessary specifications include:

- the other party's Responsibility Boundary;
- commensuration of terminology and purpose;
- non-shared domains;
- authority and stop conditions;
- preservation of history and agreement;
- disposal, withdrawal, and renegotiation;
- untranslatable residuals; and
- audit of the intermediary.

Gateway Capture occurs when the Diplomatic Port itself monopolizes communication.

---

## 14. Multiple Boundaries and Scale

An Organizational Boundary is not a single sheet.

Individuals, roles, departments, companies, industries, municipalities, states, and international organizations exist as nested or overlapping boundaries.

When all of them are compressed into a single purpose, metric, or authority, different existence phases are forced into one competitive space.

When boundaries are subdivided too far, on the other hand, no one bears responsibility for the whole.

The stability of multiple boundaries requires division of responsibility, port connections, escalation, transfer of history, mediation among competing purposes, and audit pathways that return to the whole.

---

## 15. Implementation of AI

AI functions as part of an Organizational Boundary once it is connected to pathways of input, history, authority, output, evaluation, and responsibility.

Performance is not the only important question in AI adoption.

- Through which port does the AI receive input?
- Which history can it access?
- Is its output a proposal, a judgment, or an execution order?
- Who collates the output?
- Who receives appeals?
- Who can stop it?
- Which logs are retained?
- To which Responsibility Boundary does the result return?

The minimum specification of an AI Port includes Input Boundary, Model Authority, Human Review, Uncertainty, Appeal, Logging, Escalation, Stop / Withdrawal, and Responsibility Return.

Even if AI returns fast and correct answers, its usefulness at the Organizational Boundary remains limited if it removes the human judgment field, Responsibility Boundaries, or Return Paths for appeal.

DSSI can be read as a candidate implementation that maintains the judgment field through pre-input warnings, transmission control, history retention, holding, cutoff, and responsibility return paths.

## 18. Examples of Application-Level Collation

### 18.1 Administrative Outsourcing

Even when service windows, systems, and inquiry responses are outsourced, the Responsibility Boundaries for administrative purpose, explanation, exceptions, improvement, and stopping return to the administration.

### 18.2 Medicine

Even when examinations or systems are outsourced, responsibility pathways for diagnosis, explanation, response to patients, and stopping judgments must be retained.

### 18.3 Open-Source Software

Even when code production and review are distributed, Responsibility Boundaries are required for release, compatibility, and security response.

### 18.4 AI Adoption

Even when classification, summarization, or recommendations are delegated to AI, input conditions, authority, collation, appeal, withdrawal, and explanation must remain within the Organizational Boundary.

### 18.5 Peace Design

Rather than integrating different organizations, states, and communities into one, peace design retains boundaries, Diplomatic Ports, translation, stopping, renegotiation, and Return Paths.

## 20. Non-Claim Boundaries

This document does not claim that:

- an organization is identical to a communication network;
- companies, public administrations, states, individuals, and AI are the same kind of existence;
- negentropy can be applied directly to organizational evaluation as a thermodynamic measurement;
- legal, administrative, or medical responsibility can be determined through this document alone;
- a particular organizational structure, policy, AI product, or management method should be adopted;
- port design alone can guarantee ethicality or safety;
- increasing audit, logs, or automation resolves responsibility problems; or
- this document may be used for personnel evaluation, ideological diagnosis, personality classification, or intensified surveillance.

What this document claims is that a shared purpose must be implemented as responsibility, communication, history, exceptions, and stop conditions, and that anomalies, residuals, and residue must be returned to boundary updates.

## 22. Provisional Conclusion

Purpose is not implemented merely by being declared.

Purpose becomes operational only when it creates an Organizational Boundary, allocates responsibility, opens ports, establishes protocols, retains history, processes exceptions, and possesses Return Paths for stopping and correction.

An organization is not a wall that protects the interior.

It is a boundary that determines what it receives, what it transforms that input into, what it returns, and which burdens it accepts as its own responsibility.

Functions can be delegated.

Responsibility cannot be erased through delegation.

Organizational maturity cannot be measured only by whether normal operation continues without interruption.

It is measured by whether the organization can receive anomalies, return them to Responsibility Boundaries, and update its purpose, boundaries, ports, and protocols.
