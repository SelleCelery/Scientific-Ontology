## 1. なぜ目的だけでは実装にならないのか

組織は、目的を掲げるだけでは動かない。

目的は、役割、権限、予算、評価、情報経路、例外、記録、停止条件へ変換される。

この変換が曖昧であれば、目的は現場へ届かない。

目的名だけが届き、責任、異議申立て、監査、停止権限が届かなければ、目的は命令またはスローガンへ変質する。

「安全」を掲げても、事故を報告するポートがなければ安全は実装されない。

「人を大切にする」と掲げても、疲弊を記録し、配置を修正し、業務を止める責任主体がいなければ、その目的は組織境界に接続されていない。

「AIを活用する」と掲げても、入力、権限、判断、説明、例外、撤退を処理するポートがなければ、AIは責任の空白を内部へ持ち込む。

目的を実装するとは、目的を細かい命令へ分解することではない。

目的を、責任ある通信と修正可能な履歴へ変換することである。

## 2. 境界としての組織

組織とは、単なる人の集合ではない。

本稿では、組織を次の要素を保持する動的境界として読む。

```text
Organization
  = Boundary
  + Purpose
  + Responsibility
  + Ports
  + Protocols
  + History
  + Processing Capacity
  + Return Paths
  + Boundary Update
```

### 2.1 Boundary / 境界

何を内部として扱い、何を外部として扱うかを定める。

### 2.2 Purpose / 目的

何を受け取り、何へ変換し、何を返す組織であるかを定める。

### 2.3 Responsibility / 責任

誰が許可し、監督し、説明し、改善し、停止し、履歴を保持するかを定める。

### 2.4 Ports / ポート

どの種類の通信を、どの条件で受け入れ、処理し、返すかを定める。

### 2.5 Protocols / プロトコル

受け取った通信を、誰が、どの形式へ変換し、どこへ送るかを定める。

### 2.6 History / 履歴

過去の接触、判断、例外、失敗、修正が、次の受け取り方を変える形で保持される。

### 2.7 Processing Capacity / 処理能力

どれだけの差分、例外、矛盾、苦情、危機を、外部化せず処理できるかを定める。

### 2.8 Return Paths / 返路

出力、責任、異議、修正要求、残差が、次の処理主体または原目的へ戻る経路を定める。

### 2.9 Boundary Update / 境界更新

現行の境界、役割、権限、ポート、プロトコルでは処理できない異常を受けて、組織構造を修正する。

この定義は企業だけを対象としない。

共同体、行政、学校、病院、研究組織、OSS、国家、国際組織、AIエージェント群も、異なる条件を持つ境界系として比較できる。

ただし、比較可能であることは同一であることを意味しない。

## 3. 第一義を変換契約へ落とす

組織が何をエントロピーとして受け取り、何をネゲントロピーとして返すかは、その組織が何を第一義として置くかに依存する。

組織の自己定義を、標語ではなく変換契約として表す。

| 項目 | 問い |
|---|---|
| 第一義 | 何を守り、増やし、失ってはならないものとして置くか。 |
| 受入差分 | どの未整理、苦痛、矛盾、危険、需要を内部で受け取るか。 |
| 変換 | 受け取った差分を、どの能力、手続、関係、意味へ変えるか。 |
| 返却価値 | 社会、利用者、構成員、自然、未来へ何を返すか。 |
| 禁止外部化 | 内部で処理すべき負荷を、誰へ押し流してはならないか。 |
| 責任主体 | 変換の成否、例外、失敗、説明を誰が引き受けるか。 |
| 時間射程 | どの期間まで後続条件を追跡するか。 |
| 停止条件 | 何が起きたら変換を停止し、目的へ戻るか。 |

病院であれば、痛み、病気、診断不能、ケア不足を受け取り、回復、説明、ケア、選択可能性を返そうとする。

学校であれば、未整理の経験、学習不能、孤立、知識不足を受け取り、理解、学習回路、共同探究、将来の行為可能性を返そうとする。

研究組織であれば、未整理の知識、未検証の仮説、分断された知見を受け取り、検証可能性、反例、通約可能性、公開可能な知識を返そうとする。

ここでいうエントロピーとネゲントロピーは、熱力学的な量ではなく、組織が何を未整理な負荷として受け取り、何を秩序、意味、ケア、判断可能性として返そうとするかを読む概念モデルである。

## 4. Organizational Boundary / 組織境界

組織境界とは、組織が内部、外部、通信、責任、履歴、処理能力を定義する動的境界である。

内部とは、建物の内側ではない。その組織が責任、処理、説明、履歴保持の対象として引き受ける領域である。

外部とは、無関係な領域ではない。組織の権限または目的の外側にありながら、通信、負荷、返りを交換する領域である。

境界は、目的、法令、権限、技術、危機、社会的期待、構成員の能力、委託、合併、撤退、失敗履歴によって変化する。

### 4.1 境界の曖昧化

- 誰が処理するか分からない。
- 誰が説明するか分からない。
- 誰が停止できるか分からない。
- 問題が部署間を移動し続ける。
- 利益は内部化され、負荷は外部化される。

### 4.2 境界の硬直

- 外部の変化を受け取れない。
- 例外を規則違反として処理する。
- 異議申立てを敵対として扱う。
- 内部ヒューリスティックが教義化する。
- 処理不能な差分が外部へ押し戻される。

安定した組織境界は、何を、どの条件で、どのポートから受け取り、どこへ返すかを区別できる境界である。

## 5. Responsibility Boundary / 責任境界

責任境界とは、行為だけでなく、その行為を許可し、設計し、監督し、説明し、改善し、停止し、履歴を保持する主体の境界である。

> **機能は委託できる。責任は、委託によって消すことはできない。**

外部委託、分業、自動化、AI利用は機能の配置を変える。

しかし、配置変更それ自体は責任を消去しない。

責任は、少なくとも次へ分解できる。

- 目的設定
- 設計
- 許可
- 実行
- 監督
- 受益
- 説明
- 改善
- 停止
- 履歴保持

これらが分散しても、返路が失われてはならない。

### 5.1 責任洗浄

```text
発注者
  → 委託先
  → 下請け
  → 現場担当
  → 自動化システム
  → AI出力
  → 利用者の自己責任
```

この連鎖で機能が分散しても、誰が許可したか、誰が利益を得たか、誰が異常を知り得たか、誰に停止権限があったかという履歴は残る。

責任境界は法的責任と同一ではない。法的結論は法令、契約、証拠、管轄によって判断される。

## 6. Port / ポート

ポートとは、組織境界において、特定の種類の通信を受け入れ、変換し、処理し、返すための境界口である。

組織は、単一の入口からすべてを処理できない。

研究、営業、法務、教育、採用、財務、苦情、危機、監査、外交は異なる条件を必要とする。

### 6.1 ポートの最小仕様

| 項目 | 内容 |
|---|---|
| Port Name | 名称と対象通信 |
| Purpose | なぜ必要か |
| Accepted Input | 受け入れる差分、形式、範囲 |
| Actor | 誰が利用できるか |
| Authority | 何を判断・変更できるか |
| Transformation | 入力をどの形式へ変換するか |
| Capacity | どれだけ処理できるか |
| Escalation | 処理不能時にどこへ送るか |
| Output | 誰へ何を返すか |
| Return Path | 異議、修正、追加情報をどう戻すか |
| Logging | 何を履歴として残すか |
| Stop / Reopen | 停止・再開条件 |

### 6.2 ポート類型

- Service Port / 通常業務ポート
- Exception Port / 例外ポート
- Appeal Port / 異議申立てポート
- Audit Port / 監査ポート
- Emergency Port / 緊急ポート
- Learning Port / 学習ポート
- Diplomatic Port / 外交ポート
- AI Port / AI接続ポート
- Depth Port / 深度ポート

深度ポートは、現在の論理平面で閉じない差分を、未解決のまま履歴と再照合条件を保持して送るポートである。

### 6.3 ポート不在

必要なポートがなければ、通信は消えない。

苦情は雑談になり、異常は個人の抱え込みになり、例外は規則違反になり、修正要求は離職になり、安全上の異議は沈黙になる。

### 6.4 ポート過負荷

容量を超える入力は、待機時間、定型応答、例外切捨て、説明省略、入力者への責任転嫁、現場疲弊として現れる。

## 7. Protocol / プロトコル

プロトコルとは、通信を受けた後、誰が、何を、どの条件で、どの形式へ変換し、どこへ返すかを定める境界手続である。

プロトコルは、単なるマニュアルではない。

```text
Who
What
Conditions
Transform
Route
Return
Escalate
Log
Stop / Reopen
```

プロトコルが硬直すると、規則に適合するものだけが現実として扱われる。

例外をなくすのではなく、誰が、どこで、どの責任をもって扱うかを定める必要がある。

---

## 8. Processing Capacity / 処理能力

処理能力とは、人員数や計算量だけではない。

- 入力を理解する能力
- 翻訳する能力
- 例外を保留する能力
- 複数目的の競合を扱う能力
- 履歴を検索する能力
- 説明を返す能力
- 異議を再照合する能力
- 長期的な後続条件を追う能力

成熟した組織は、保留状態を持つ。

保留には、理由、責任主体、再開条件、再照合期限、入力者への説明、履歴保持が必要である。

処理能力を超えた入力は、現場の残業、顧客の待機、家族のケア負担、自然環境への排出、将来世代の修復費用へ外部化される。

---

## 9. History, Logging, and Audit / 履歴・ログ・監査

ログとは出来事を保存した記録である。

履歴とは、その記録が次の判断、責任、受け取り方、境界更新へ接続される構造である。

大量のログを保存しても、検索、照合、権限、改善経路がなければ履歴として機能しない。

少なくとも、入力、判断、根拠、実行、例外、保留、異議、再判断、停止、目的・境界・プロトコル変更を区別して記録する。

監査は、規則遵守だけではない。

- 第一義と運用が一致しているか。
- ポートが必要な通信を受け取れているか。
- 責任が下流へ消えていないか。
- 負荷が外部化されていないか。
- 例外が境界更新へ届いているか。
- 停止条件が実行可能か。

監査系自身にも盲点がある。

同じ異常が後から繰り返し発見されるなら、対象だけでなく観測系を監査する必要がある。

## 10. 正常・異常・例外・境界更新

正常処理を仕組みに委ねる目的は、人間が正常を見続けることではない。

人間の注意を、逸脱、例外、矛盾、未処理へ移すことである。

異常は、破綻の予兆であると同時に、環境変化または新しい需要の兆候でもある。

最も見えにくいのは、成果を出している異常である。

- 特定個人の抱え込み
- 暗黙知への依存
- 残業による吸収
- 善意による例外処理
- 利用者による自己補完
- 外部環境への負荷転嫁

境界更新は、次の循環で行う。

```text
正常処理を仕組みに委ねる
  ↓
逸脱・異常・例外を観測する
  ↓
現行境界の限界を特定する
  ↓
目的・責任・ポート・プロトコルを再照合する
  ↓
新しい正常処理へ組み込む
  ↓
監査系の盲点を再検査する
```

## 11. Boundary CAの実装

境界CAを成立させるには、観測だけでは足りない。

| 問い | 組織実装 |
|---|---|
| 誰が疲弊したか | 負荷指標、面談、異議、離脱履歴 |
| 何が不可視化されたか | 例外記録、未分類入力、監査の監査 |
| どこへコストが移ったか | 外部化先、待機、無償労働、環境負荷 |
| どの責任境界が曖昧か | 許可・設計・監督・説明・停止の役割表 |
| どの返路が失われたか | Appeal Port、再審査、エスカレーション |
| 何を修正できるか | 手順、境界、指標、共有、目的、停止 |

監査結果を記録しても、権限、指標、目的を変えられなければ、CAは儀式化する。

## 12. 外部化・残差・残渣

外部化そのものが常に悪いわけではない。

分業、委託、廃棄、排出、保険、移転は必要な場合がある。

問題は、外部化した負荷と責任の返路が失われることである。

残差は、現行の分類、説明、プロトコルでは閉じきれないが、再照合可能な差分である。

残渣は、処理後も身体、制度、関係、環境、未来に沈殿し、作用し続ける履歴的負荷である。

組織のネゲントロピーは、内部秩序だけでは評価できない。

内部を整えるために外部へ過大な残渣を押し出しているなら、その秩序は局所的である。

## 13. 外交とゲートウェイの組織実装

外交は国家だけに存在する機能ではない。

企業、行政、病院、大学、OSS、研究組織、共同体の間にも、異なる責任境界を接続する外交機能がある。

外交ポートは、相手を内部化せず、異なる境界、履歴、目的、制約を保持したまま通信可能性を維持する。

ゲートウェイは、異なるプロトコル間で通信を変換する。

必要な仕様は次である。

- 相手の責任境界
- 用語と目的の通約
- 非共有領域
- 権限と停止条件
- 履歴と合意の保存
- 破棄、撤退、再交渉
- 翻訳不能残差
- 仲介者監査

外交ポート自身が通信を独占すると、ゲートウェイ捕捉が起きる。

## 14. 多重境界と規模

組織境界は一枚ではない。

個人、役割、部署、企業、業界、自治体、国家、国際組織は、入れ子または重なり合う境界として存在する。

すべてを単一の目的、指標、権限へ圧縮すると、異なる存在相が一つの競争空間へ押し込められる。

一方、境界を細分化しすぎると、誰も全体責任を持たない。

多重境界の安定には、責任分担、ポート接続、エスカレーション、履歴受渡し、競合目的の調停、全体へ返す監査経路が必要である。

## 15. AIへの実装

AIは、入力、履歴、権限、出力、評価、責任の経路へ接続された時点で、組織境界の一部として機能する。

AI導入で重要なのは、性能だけではない。

- どのポートから入力を受けるか。
- どの履歴へアクセスできるか。
- 出力は提案か、判断か、実行命令か。
- 誰が照合するか。
- 誰が異議を受けるか。
- 誰が停止できるか。
- どのログを残すか。
- どの責任境界へ返すか。

AI Portの最小仕様には、Input Boundary、Model Authority、Human Review、Uncertainty、Appeal、Logging、Escalation、Stop / Withdrawal、Responsibility Returnを含める。

AIが高速で正しい答えを返しても、人間の判断場、責任境界、異議の返路を消すなら、組織境界上の有用性は限定される。

DSSIは、入力前警告、送信制御、履歴保持、保留、切断、責任返路によって判断場を維持する実装候補として読める。

## 16. 通信ネットワークとの通約

本稿は、組織を通信ネットワークへ還元しない。

| 組織モデル | ネットワーク類比 |
|---|---|
| 組織 | Node / Administrative Domain |
| 組織境界 | Interface |
| ポート | Port |
| プロトコル | Protocol |
| 権限 | ACL |
| 委任 | Proxy |
| 外交 | Gateway / Routing Policy |
| 履歴 | Log / State History |
| 監査 | Monitoring / Audit |
| 例外処理 | Exception Handling |
| 境界更新 | Configuration / Topology Update |

組織には、意味、責任、権力、身体、法、信頼、文化、不可逆な履歴がある。

ネットワーク類比は、通信条件を明示し、シミュレーション可能な構造へ落とすために用いる。

## 17. シミュレーションと形式化候補

最小単位は次の通りである。

```text
Agent
Boundary
Purpose
Responsibility Boundary
Port
Protocol
Message
History
Processing Capacity
Residual / Residue
Return Path
Boundary Update
```

状態変数候補には、入力件数、待機時間、未処理件数、例外率、異議率、再判断率、外部化量、責任返路の長さ、履歴検索可能性、停止権限、境界更新頻度、特定個人への集中度がある。

遷移候補は次の通りである。

```text
Receive
  → Accept / Hold / Reject / Redirect
  → Transform
  → Decide
  → Return
  → Appeal
  → Re-collate
  → Update Boundary
```

## 18. 適用照合例

### 18.1 行政委託

窓口、システム、問い合わせ対応を委託しても、行政目的、説明、例外、改善、停止の責任境界は行政側へ戻る。

### 18.2 医療

検査やシステムを外注しても、診断、説明、患者への応答、停止判断の責任経路を保持する必要がある。

### 18.3 OSS

コード作成やレビューが分散しても、リリース、互換性、セキュリティ対応には責任境界が必要である。

### 18.4 AI導入

分類、要約、提案をAIへ委託しても、入力条件、権限、照合、異議、撤退、説明を組織境界へ残す。

### 18.5 平和設計

異なる組織、国家、共同体を一つへ統合するのではなく、境界、外交ポート、翻訳、停止、再交渉の返路を保持する。

## 19. 組織境界の失敗類型

- Boundary Ambiguity / 境界曖昧化
- Boundary Rigidity / 境界硬直
- Port Collapse / ポート崩壊
- Port Absence / ポート不在
- Responsibility Dilution / 責任希釈
- Protocol Absolutization / プロトコル絶対化
- Logging without Return / 返路なき記録
- Audit Ritualization / 監査儀式化
- Single-Metric Compression / 単一指標圧縮
- Successful Anomaly / 成功している異常
- Responsibility Laundering / 責任洗浄
- False Closure / 偽閉鎖
- Gateway Capture / ゲートウェイ捕捉

## 20. 非主張境界

本稿は、次を主張しない。

- 組織を通信ネットワークと同一視する。
- 企業、行政、国家、個人、AIが同じ存在である。
- ネゲントロピーを熱力学的測定量として組織評価へ直接用いる。
- 法的責任、行政責任、医療責任を本稿だけで判定できる。
- 特定の組織構造、政策、AI製品、経営手法を推奨する。
- ポート設計だけで倫理性や安全性を保証できる。
- 監査、ログ、自動化を増やせば責任問題が解決する。
- 本稿を人事評価、思想診断、人格分類、監視強化に使ってよい。

本稿が主張するのは、共有目的を責任、通信、履歴、例外、停止条件へ実装し、異常、残差、残渣を境界更新へ返す必要があるということである。

## 21. 開いている問い

1. 複数の第一義が競合したとき、誰が最終判断を行うべきか。
2. 法的、道徳的、設計上、履歴上の責任をどこまで分離できるか。
3. 処理能力を量だけでなく意味・照合能力としてどう評価するか。
4. 残差を保持しながら運用を停滞させない保留プロトコルは可能か。
5. 異議申立てポートが実質的な境界更新へ届く条件は何か。
6. AIエージェント間の責任返路を複数組織間でどう保持するか。
7. 国家、自然、未来世代の間で誰がBoundary CAの主体になりうるか。

## 22. 暫定結論

目的は、掲げただけでは実装されない。

目的は、組織境界を作り、責任を配置し、ポートを開き、プロトコルを定め、履歴を残し、例外を処理し、停止と修正の返路を持ったとき、初めて運用可能になる。

組織とは、内部を守る壁ではない。

何を受け取り、何へ変換し、何を返し、どの負荷を自らの責任として引き受けるかを定める境界である。

機能は委託できる。

責任は、委託によって消すことはできない。

組織の成熟は、正常を止めないことだけでは測れない。

異常を受け取り、責任境界へ返し、目的、境界、ポート、プロトコルを更新できるかによって測られる。
